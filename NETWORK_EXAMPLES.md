# Official networking examples and URnetwork adapters

This matrix records the primary documentation checked on **2026-09-15**, the networking operation each ecosystem starts with, and the corresponding executable in this repository. Sources describe their own APIs; the mapping to URnetwork is the integration implemented by the linked local example. API availability and dependency pins belong to each language's build and [installation guide](README.md).

## Shared interpretation

Direct adapters preserve the destination hostname until the SDK connection is created, so DNS and address selection remain on the Device path. Where a library requires an OS socket, the [Go loopback proxy](go/socket/README.md) supplies that local connection and uses `Device.DialContext` for the upstream. The proxy must be explicitly configured in the HTTP client; it does not change unrelated process or system traffic.

A UR connection handle is not a kernel descriptor. Do not pass it to `select`, `poll`, an OS socket option, or a TLS library that requires a native socket. The [socket guides](README.md) distinguish library-owned TLS from SDK TLS/DTLS and describe deadlines, partial I/O and UDP Happy Eyeballs. Keep certificate and hostname verification enabled.

The SDK's browser-shaped Direct Sockets surface is an implementation profile over a UR Device. It is distinct from Chrome's [native Direct Sockets implementation for Isolated Web Apps](https://developer.chrome.com/docs/iwa/direct-sockets). Neither raw TCP/UDP nor hosted HTTP support implies support for the peer [URMS protocol](MESSAGES_PROTOCOL.md).

These links establish available extension points as of the checked date; they do not claim that every upstream version or optional feature was run here. Local build manifests retain the versions and the individual guides state verification and runtime requirements.
